Topic 1 · SOQL

SOQL: querying Salesforce records

SOQL (Salesforce Object Query Language) reads records from one object. In Apex you put the query in square brackets and it returns a List of records.

Choose the fields you need, then filter with WHERE using =, !=, LIKE, IN and AND / OR.

List<Account> accs = [
    SELECT Id, Name, Industry
    FROM Account
    WHERE Industry = 'Technology' AND Name LIKE 'Acme%'
];

Sort the results and cap how many rows come back.

List<Opportunity> opps = [
    SELECT Id, Name, Amount
    FROM Opportunity
    WHERE StageName = 'Closed Won'
    ORDER BY Amount DESC
    LIMIT 10
];

A colon before a variable name passes an Apex value into the query. It is also the safe way to avoid injection.

Set<Id> accIds = new Set<Id>{ acc1.Id, acc2.Id };
String city = 'Nagpur';

List<Contact> cons = [
    SELECT Id, LastName FROM Contact
    WHERE AccountId IN :accIds AND MailingCity = :city
];

Summarise data with COUNT(), SUM(), AVG(), MIN(), MAX() and GROUP BY. These return AggregateResult.

for (AggregateResult ar : [
    SELECT StageName, COUNT(Id) total, SUM(Amount) amt
    FROM Opportunity GROUP BY StageName
]) {
    System.debug(ar.get('StageName') + ': ' + ar.get('total'));
}
Topic 2 · Relationship queries

Relationship queries: one query, related data

Start from the child and reach up to the parent's fields with dot notation.

List<Contact> cons = [
    SELECT Id, LastName, Account.Name, Account.Owner.Name
    FROM Contact
];
System.debug(cons[0].Account.Name);

Start from the parent and pull its children with a subquery that uses the child relationship name.

List<Account> accs = [
    SELECT Id, Name,
        (SELECT Id, LastName FROM Contacts)
    FROM Account
];
for (Account a : accs) {
    System.debug(a.Name + ' has ' + a.Contacts.size() + ' contacts');
}

For custom relationships the name ends in __r (parent) or is the plural child relationship name ending in __r.

// Child to parent
SELECT Id, Project__r.Name FROM Task__c

// Parent to child
SELECT Id, (SELECT Id FROM Tasks__r) FROM Project__c

Rule of thumb: dot goes up to a parent, subquery goes down to children.

Topic 3 · SOSL

SOSL: search across objects

SOSL (Salesforce Object Search Language) searches text across several objects at once. It returns a List<List<SObject>>, one inner list per object, in the order of your RETURNING clause.

List<List<SObject>> results = [
    FIND 'Acme*' IN ALL FIELDS
    RETURNING Account(Id, Name), Contact(Id, LastName), Lead(Id, Company)
];

List<Account> accs = (List<Account>) results[0];
List<Contact> cons = (List<Contact>) results[1];
FeatureSOQLSOSL
SearchesOne object (plus related)Many objects at once
Best whenYou know the object and fieldsYou only know the text to find
ReturnsList of recordsList of Lists of records
MatchingExact or pattern (LIKE)Word-based text search index
Topic 4 · DML

DML: saving changes to the database

Creates new records. Once inserted, the record gets its Id.

Account acc = new Account(Name = 'Acme Corp');
insert acc;
System.debug(acc.Id);

Changes existing records. The record must already have an Id, usually from a query.

Account acc = [SELECT Id, Name FROM Account LIMIT 1];
acc.Name = 'Acme Global';
update acc;

Moves records to the Recycle Bin. Use undelete to restore them.

List<Contact> old = [SELECT Id FROM Contact WHERE LastName = 'Test'];
delete old;

Inserts or updates in one step. It matches on Id, or on an external Id field you name.

List<Account> accs = new List<Account>{
    new Account(Name = 'Acme', External_Id__c = 'A-100'),
    new Account(Name = 'Globex', External_Id__c = 'G-200')
};
upsert accs External_Id__c;

The Database class does the same jobs but with allOrNone = false lets good records save even if some fail.

Database.SaveResult[] results = Database.insert(accs, false);
for (Database.SaveResult sr : results) {
    if (!sr.isSuccess()) {
        System.debug(sr.getErrors()[0].getMessage());
    }
}

Always pass a whole List to one DML statement. Never put DML inside a loop.

Topic 4 · Governor limits

Governor limits: the rules of the shared platform

Salesforce is multitenant, so every transaction has hard limits. Break one and the whole transaction fails with an uncatchable exception.

Limit (per transaction)Synchronous
SOQL queries issued100
Records retrieved by SOQL50,000
SOSL queries issued20
DML statements issued150
Records processed by DML10,000
CPU time10,000 ms
Heap size6 MB

No SOQL in loops

Query once, before the loop, using a Set of Ids.

No DML in loops

Add records to a List, then run one DML statement.

Check the limits

Use Limits.getQueries() to see how many you have used.

Asynchronous Apex (Batch, Queueable, Future) gets higher limits for some resources, for example 200 SOQL queries, 12 MB heap and 60,000 ms CPU. Always confirm current numbers in the Apex Developer Guide.

Recap

Key takeaways

1. SOQL

Read records from one object with SELECT, WHERE, ORDER BY and LIMIT. Use bind variables for Apex values.

2. Relationships

Dot notation goes up to a parent. A subquery goes down to children.

3. SOSL

Search text across many objects at once. Results are a List of Lists.

4. DML & limits

Insert, update, delete, upsert on whole Lists. Stay inside 100 queries and 150 DML statements.
