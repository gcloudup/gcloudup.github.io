Objects: what code sees

Every object is an SObject type in Apex. Standard objects such as Account have no suffix. The suffix on a custom API name tells you what you are dealing with.

(none)Standard object or standard fieldAccount, Contact.Email

__rRelationship name of a custom lookup, used to reach the parentCustomer__r.Name
__mdtCustom metadata typeSetting__mdt
__xExternal objectOrder__x
__ePlatform eventOrder_Event__e
__bBig objectArchive__b

Topic 1 · Objects, fields, relationships

Relationships: the three you need

What
A loose link. The parent is optional.
Behavior
The child keeps its own owner and sharing. Deleting the parent does not delete the child by default.
Dev lens
The field holds an Id that can be null, so always check for null in code. Native roll-up summary fields are not available.
What
A tight link. The parent is required.
Behavior
The child inherits owner and sharing from the parent, is deleted with it (cascade delete), and the parent can have roll-up summary fields.
Dev lens
You cannot insert a child without a parent Id. A custom object can have up to two master-detail fields.
What
A junction object with two master-detail fields, linking two objects together.
Example
Enrollment__c connects Student__c and Course__c.
Dev lens
Query through the junction: SELECT Student__r.Name, Course__r.Name FROM Enrollment__c
Topic 1 · Objects, fields, relationships

Querying across relationships

Use dot notation with the parent relationship name.

SELECT Id, LastName, Account.Name, Account.Industry
FROM Contact
LIMIT 5

In Apex, read it as c.Account.Name.

Use a subquery with the plural child relationship name.

SELECT Id, Name,
       (SELECT Id, LastName FROM Contacts)
FROM Account
LIMIT 5

In Apex, the children come back as a list: acc.Contacts.

For custom lookups, both names end in __r.

// Child to parent
SELECT Id, Name, Customer__r.Name
FROM Invoice__c

// Parent to child
SELECT Id, Name, (SELECT Id FROM Invoices__r)
FROM Account

The child relationship name (here Invoices) is set on the lookup field when you create it.

Topic 2 · Schema Builder & API names

Labels are for people, API names are for code

The label is what users see and can change or translate. The API name is what Apex, SOQL, Flow and integrations use. Type a label to see the API name Salesforce would suggest.

API nameLoyalty_Tier__c
If it is a lookup field, relationship nameLoyalty_Tier__r

Rules: letters, numbers and underscores only, starts with a letter, no spaces, no double or trailing underscores. Change an API name later and every reference to it can break.

Topic 2 · Schema Builder & API names

Where to find the exact name

  • In Setup: Object Manager, pick the object, then Fields & Relationships. The Field Name column is the API name.
  • In the CLI: describe an object from the terminal.
  • In Apex: ask the schema at runtime.

Topic 2 · Schema Builder & API names

Good naming habits

Choose it once

Pick the API name carefully at creation. Renaming later can break code, flows, reports and integrations.

Be descriptive

Use names like Renewal_Date__c, not Date1__c. Future you will thank you.

Stay consistent

Agree a convention with your team for underscores, prefixes and singular versus plural names.

Code uses API names

Never depend on labels in code. Labels can be edited or translated at any time.

Topic 3 · Flow vs programmatic

Flow: the declarative automation tool

Flow is Salesforce's main tool for automation without code. Pick a type to see what it is for.

Runs when
A record is created, updated or deleted.
Good for
Updating fields, creating related records, sending emails. A before-save flow updates the same record quickly, with no extra save step. An after-save flow can also change other records.
Runs when
A user starts it, from a button, page or app.
Good for
Guided wizards and forms that collect input and create or update records.
Runs when
On a schedule, for example every night.
Good for
Regular clean-up, reminders and updates across a set of records.
Runs when
Another flow, Apex code or an API call starts it.
Good for
Reusable logic that other automation or code can call.

Flow and Apex compared

AreaFlowApex
Speed to buildFast, visual builderSlower, code and review
Who maintains itAdmins and developersDevelopers
TestingDebug in Flow Builder, plus flow tests for record-triggered flowsUnit tests required, with 75% coverage to deploy to production
Complex logicGood for straightforward logicFull control: collections, maps, algorithms, error handling

Rule of thumb: clicks before code, and use code when clicks cannot do the job cleanly.

Topic 3 · Flow vs programmatic

Working well together

Start with Flow

Use Flow for record automation, then add code only where needed.

Before-save for same-record updates

They run faster because they need no extra save.

Keep one owner

Avoid several flows and triggers doing overlapping work on one object. Know the order of execution.

Bulk-safe always

No queries or saves inside loops, in Flow or in Apex.

Bulk-safe pattern in Apex

// Query once, outside the loop
Set<Id> accIds = new Set<Id>();
for (Contact c : Trigger.new) { accIds.add(c.AccountId); }

Map<Id, Account> accs = new Map<Id, Account>(
    [SELECT Id, Name FROM Account WHERE Id IN :accIds]
);
